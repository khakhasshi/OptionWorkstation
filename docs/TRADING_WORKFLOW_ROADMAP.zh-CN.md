# 交易工作流与期权因子可视化开发路线图

状态：规划，尚未实现的能力不构成当前产品承诺。  
记录日期：2026-09-30。  
适用项目：Option Workstation；期权因子计算拟复用独立项目 OptionTimeSeriesFactor。

本文把未来开发整理为可拆分、可验证的工作项，覆盖“选合约 → 评估策略 →
观察委托与成交 → 管理持仓 → 复盘信号”。P0 表示下一阶段优先建设，P1 表示
依赖基础能力后的增强；优先级不代表交付日期。

## 1. 当前能力与范围

已有能力包括历史同步回放、两种实时行情源、镜像期权链、波动率分析、到期
收益图、固定 Spot/IV/时间情景矩阵、账户与今日订单只读查询，以及审计记录。
界面已有总览、波动率、交易、记录四个工作区，并支持图表按需挂载和期权链
窗口化渲染。

当前写交易操作仅支持通过门禁的 Longbridge 模拟账户，采用逐腿限价提交；
账户和今日订单的只读查询不等于实盘下单支持。ThetaData 仅提供行情。
当前没有持仓、成交明细和改单的完整工作台接口。请求撤销此前已报腿不等于
成交回滚，也不代表多腿原子成交。

本路线图建设交易决策辅助、只读账户风险和模拟流程，保持项目现有“不支持
实盘账户下单、不规划实盘自动交易”的范围。因子导入不会授予交易权限。
参考 [模型限制](MODEL_LIMITATIONS.md)、[安全策略](../SECURITY.md) 和
[贡献约束](../CONTRIBUTING.md)。

## 3. 交易功能验收要求

### TW-01：联动报价与委托抽屉

- 选择对象使用完整合约身份（标的、到期日、行权价、Call/Put、供应商合约 ID），
  同执行价不同到期日的合约不会串联；切换对象后旧请求不能覆盖新选择。
- 显示 Bid/Ask、可用的挂单量、绝对及相对价差、供应商时间戳、接收时间与报价年龄。
  无挂单量权限或源字段缺失时显示不可用，不能推断深度或可成交数量。
- 明确组合方向、比例、数量、乘数、净借记/净贷记和计价时刻；理论价格、中间价、
  买入按 Ask / 卖出按 Bid 的报价估算分别标识，估算不保证成交。
- 报价陈旧、腿不齐或异步截面不一致时保留可解释的受限状态；查看详情不会提交订单。

### TW-02：动态盈亏图

- 同屏叠加当前模型估值曲线、指定时间曲线和到期收益线；十字线同步显示所选
  价格、剩余期限、IV 假设、盈亏和组合 Greeks。
- 时间与 IV 调节在明确范围内工作；高频拖动合并请求，只接受最新情景结果。
- 当前真实 Bid/Ask 的平仓估算与假设价格下的模型估值区分呈现；未来报价未知时
  不得将模型估值命名为“可执行平仓价”。费用、滑点及乘数假设可查看。
- 先展示后端已返回的组合 Greeks。现有 Margin 是模型估算，POP 是模型概率；
  界面不得把它们称为券商确认的保证金或实测胜率。
- 覆盖空策略、缺腿、失效报价、临近到期和无限风险等状态；保留现有模拟门禁。

### TW-03：持仓风险仪表盘

- 接入账户、持仓及成交只读数据，展示同步时间、持仓数量、可用数量、成本币种、
  未实现盈亏来源；模型标记与券商返回值分别注明。
- 按标的、到期日和明确归组的策略汇总敞口；Delta/Gamma/Vega/Theta 的单位、
  乘数及转换方式一致。缺行情的持仓不能静默当零风险，需展示覆盖率。
- 支持“现有组合”和“加入候选策略后”的同口径压力比较；跨币种汇总需明确汇率
  与时刻，数据不足则分币种展示。
- 部分成交和未成交委托的潜在风险独立显示，避免在持仓和挂单中重复计入。
- 日历、跨期与滚仓需要扩展逐腿到期日和快照输入；不沿用当前单到期日接口冒充支持。

### TW-04：订单与成交进度面板

- 面板常驻交易工作区，按策略关联各腿和成交；接入推送或有界轮询，并在断线恢复后
  通过权威订单/成交查询补齐和对账。
- 状态机处理重复、乱序、部分成交、请求超时和撤单竞态。已发送撤单请求仍显示
  “撤单处理中”，收到确认后才进入已撤状态；提交成功不显示为成交成功。
- 显示已成交/剩余数量、成交均价、订单和最后事件时间、拒单原因及临时腿间敞口。
  价差成本需绑定下单时的报价基准与实际成交，缺基准时保持不可用。
- 自动化验收使用合成事件与模拟接口，不触发真实账户写操作。
- Longbridge 官方已列出多腿订单接口。接入前需验证安装的 SDK、账户资格、
  策略类型、净价方向及实际成交语义；“组合提交”本身不证明支持任意组合或原子成交。
  参考 [官方多腿订单接口](https://open.longbridge.com/zh-CN/docs/trade/order/submit_multileg)。

### TW-05：合约流动性热图

- 以到期日和行权价组织数据，Call/Put 可切换；色阶选择价差、新鲜度、成交量或 OI，
  图例明确单位和有效时刻；不同单位不共用同一色阶。
- 支持 DTE、Delta、价差和最低流动性过滤，选择格子可定位合约并加入策略草稿。
- OI 以数据实际可用日期对齐，不把日级统计解释为盘中新变化。OI 要在日终清算后
  更新，参见 [OCC / OIC 说明](https://www.optionseducation.org/referencelibrary/faq/general-information)。
- 大合约池使用分页、可见区域查询或订阅预算；空值、陈旧数据和未订阅区间有独立状态。

### TW-06：盘中序列与提醒

- 联动十字线展示同一时刻的价格、IV、Skew 和组合价格；每条序列带合约/选腿规则、
  模型及报价口径。换合约或换模型时展示边界，不生成伪连续变化。
- 提醒规则包含作用对象、阈值、触发方向、持续条件、冷却时间和有效时段，支持去重、
  暂停、恢复及事件追溯。数据陈旧提醒按时钟计算，不依赖新行情到达。
- 提醒跳转到触发时刻证据或当前对象，两者清楚区分。回放历史触发记录与实时提醒
  分开，拖动回放进度不会重复发送实时通知。

## 4. DSL 因子工作区

目标是让用户看到信号后，能回答：哪组合约、什么输入、为何触发、当时报价是否可用、
对策略风险有什么影响。表达式可视化、信号规则、研究评价、真实成交使用不同记录类型。

### 4.1 可视化组成

| 视图 | 设计与验收重点 |
| --- | --- |
| 价格与因子联动图 | 标的价格、组合报价、因子共用时间轴与十字线；不同量纲分轴/分面板，时间空缺不插值伪装为有效值。 |
| 信号事件轨道 | 标记阈值穿越、条件满足、报价失效及恢复；点击事件打开相同时间的冻结截面和风险预览，不能跳到最新行情替代证据。 |
| 因子解释面板 | 展示原始输入、表达式节点中间值、窗口样本数、均值/标准差、最终值和实际腿 IDs；不适用的解释项保持空白。 |
| 多因子状态矩阵 | 按策略/标的比较当前状态，显示预热、缺失、陈旧、有效及计算错误；筛选条件和有效样本覆盖率可查看。 |

### 4.2 导入契约

首版通过有版本的 JSON 包导入表达式及元数据；可提供粘贴表达式的入口，但缺少
口径信息时必须补全后才能计算。以下为拟定结构，不是现有 API 或可直接执行的文件：

```json
{
  "schema_version": "option-workstation.factor-import/v1",
  "factor_id": "example-iv-zscore",
  "expression": "ts_zscore(iv_mid, 60)",
  "dsl_version": "ts-dsl-v2",
  "task_hash": "<source-task-hash>",
  "protocol_hash": "<source-protocol-hash>",
  "engine_version": "<source-engine-version>",
  "trade_object": {"kind": "fixed_contract", "contract_ids": ["<contract-id>"]},
  "sampling": {"frequency": "1m", "timezone": "America/New_York", "closed_only": true},
  "window": {"unit": "observations", "grouping": "source_state_key", "cross_session": false},
  "feature_contract": {"iv_mid": {"unit": "ratio", "source": "model_mid"}},
  "signal_rule_id": null
}
```

导入还需验证完整研究协议及其哈希、实际支持的版本、字段来源/单位、定价模型、
交易日历、缺失值与跨日处理。固定合约、固定组合、动态选腿分别定义身份；动态选腿
保存规则版本，并在输出中带实际腿 IDs。示例表达式只说明功能，不表示已经通过收益评价。

信号阈值、方向、冷却等保存在独立版本的规则中，绑定因子与协议。标准化或阈值参数
若来自训练样本，需保存训练范围和冻结参数，不能使用整个回放区间的未来分布。

### 4.3 与现有研究引擎的兼容约束

2026-09-30 源码核对的接入点位于外部项目 OptionTimeSeriesFactor：

- `src/option_ts_factor/dsl.py`：AST 白名单、Polars 编译、`apply_factor()`。
- `src/option_ts_factor/config.py`：ResearchProtocol 的 DSL/引擎/模型版本与假设。
- `src/option_ts_factor/search.py` 和 `pipeline.py`：表达式、候选身份、task/protocol hash
  及研究记录。现有统计/样本接口还需要增加有范围限制的逐时间因子输出。

接入适配器必须处理以下差异，并用合成输入验证一致性：

1. **同名特征不等价。** 研究端 IV 与 `spread_pct` 使用小数比例，工作站链表使用百分数；
   研究端 `log_moneyness = ln(S/K)`，工作站同名字段为 `ln(K/F)`。需按源模型重建输入，
   不能仅按字段名映射。多腿研究特征的带符号加权定义也不等于单腿值或净持仓 Greeks。
2. **窗口按观测行数计。** 当前 `ts_zscore(iv_mid, 60)` 要求同组满 60 个观测；换腿或缺分钟
   会改变实际时间跨度。`ts_delta(x, 60)` 还需要前 60 行，EMA 的预热语义另行保留。
3. **合约身份决定序列。** 现有分组包含实际合约/组合及交易日。相同策略再次出现时是否
   续用此前样本、缺口是否重置，都必须匹配源协议；不能默认为连续 60 分钟。
4. **实时与回放要逐点一致。** 只在定义的采样点更新状态，心跳不追加样本；未完成 bar
   如需预览应单独标识，不能混入正式已确认信号。禁止未来引用、整段事后归一化及回填未来值。
5. **缺失不是零。** 预热不足、无效报价、零方差、除零、数据陈旧和计算失败分别返回状态，
   不把非有限值强制转零。OI 的观测日期与可用时刻、模型特征来源应随输入保留。
6. **时序与截面算子分开。** `cs_rank` 需要同时间完整横截面；单合约或部分订阅集合不足时
   明确拒绝或返回不可用，不能默默用残缺样本计算。

### 4.4 首版数据流程与接口草案

```text
导入表达式和协议
  → 校验版本、字段、身份与范围
  → 原研究引擎加载预热并生成因子序列
  → 工作站缓存、时间轴联动和解释
  → 信号事件冻结证据
  → 用户打开策略风险预览
```

第一版复用原因子内核，新增适配接口，不在 React 或 Rust 中未经核验重写 DSL。
表达式不能执行任意 Python/JavaScript，也不能调用账户写操作。接口需限制表达式长度、
复杂度、窗口、标的、日期范围、输出点数及任务时间，并支持取消与错误状态。

逐点结果的拟定字段至少包括：

- `timestamp`、`available_at`、`state_key`、实际合约/腿 IDs；
- `factor_id`、DSL/引擎版本、task/protocol hash 和输入快照标识；
- `value`（可空）、`status`、所需/已有样本数、缺失与陈旧原因；
- 关联的特征来源、单位和解释记录引用。

解释记录可按选中时间点加载，避免把每个节点的完整历史都推到前端。
因子曲线回放不等于包含成交、费用、持仓与拒单账本的策略回测；研究评价输出应有独立入口。

### 4.5 性能与验收

- 历史结果按表达式、协议、数据版本、对象身份、时间范围和采样规则缓存；相同参数复用，
  协议或数据修订后失效。先加载当前视窗与所需预热，后台扩展有明确进度。
- 实时计算位于独立任务/进程，队列与内存有界。新增样本增量传输；发生修订或补数时按时间点
  替换并重算受影响窗口，不能一律追加或静默丢掉必要输入。
- 图表只绘制当前工作区与可见区域；显示抽稀不改变信号计算、事件记录或原始结果。
- 先用原因子引擎计算有限窗口。后续移植 Rust 或增量算子时，对同一合成输入与经授权样本
  做逐点对照，明确浮点容差、预热、缺失、分组和修订语义。
- 回归覆盖：短样本、缺分钟、跨日、夏令时、换腿及再次出现、重复/乱序样本、心跳、断线恢复、
  零方差、陈旧报价、协议变更与取消作业。高倍回放中的因子、信号和截面保持同一已确认时间。

## 6. 完成标准

- 用户可以从一个合约或因子事件追到输入、时刻、策略风险和相应订单状态。
- 待开发项有独立验收记录后才能标记完成；历史数据验证、模拟交易验证与真实账户只读验证
  分别记录，不能用单元测试或图表截图替代。
- 所有图表覆盖空、预热、部分、陈旧、错误及正常状态，并通过桌面/窄屏、键盘与高频更新检查。
- 凭证、账户标识、供应商原始数据和私有研究记录不进入公共仓库或 PR 附件。
